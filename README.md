# Unified Perception

A **StreamPETR-style** transformer for **multi-view, multi-person 3D human keypoint
estimation**. It adapts the StreamPETR autonomous-driving pipeline (multi-view 2D
images + camera calibration → a query-based transformer detector with temporal
memory and Hungarian set matching) to the human-pose domain from the
`human_prior` project.

Key differences from `human_prior`:

- **No intermediate 2D keypoint detector.** The model consumes raw calibrated
  camera images directly and is supervised end-to-end by mocap ground truth.
- **Arbitrary number of people.** Like StreamPETR's object queries, each query
  represents a candidate person; predictions are matched to ground-truth people
  with a Hungarian matcher (the `human_prior` datasets contain one person, but
  the code makes no such assumption).

## How it maps to StreamPETR

| StreamPETR | Here |
|---|---|
| EVA-ViT image backbone | YOLO pose pre-head feature extractor (`models/yolo_backbone.py`) |
| PETR 3D position encoding (lidar frame) | `CameraPositionEncoder3D` in the static world frame (`models/position_encoding.py`) |
| Object queries → 3D boxes | person queries → 3D keypoints (`models/petr_head.py`) |
| Temporal streaming memory (ego-aligned) | query propagation across frames, static world (`models/detector.py`) |
| `HungarianAssigner3D` + L1/focal loss | `hungarian_match` + focal/L1 (`models/matcher.py`, `models/losses.py`) |
| nuScenes data + mmdet3d configs | lightweight dataclass config + local data-provider registry |

Everything is plain PyTorch — no mmdet/mmcv registry stack or config-by-string.

## Layout

```
unified_perception/
  config.py            # lightweight dataclass config (+ YAML / CLI overrides)
  constants.py         # 12-joint skeleton definition
  data/                # geometry, provider interface/registry, backends, dataset, transforms, render
  models/              # yolo_backbone, vit(fallback), position_encoding, transformer, petr_head, matcher, losses, detector
  engine/              # train loop, eval loop, metrics
tools/
  preprocess.py        # optional synthetic generator for smoke tests
  train.py             # train
  evaluate.py          # evaluate a checkpoint
  visualize.py         # overlay GT/predictions on camera views
configs/
  synthetic_small.yaml # quick smoke-test config
```

## Quick start

```powershell
pip install -r requirements.txt

# 1. Generate a small synthetic multi-view, multi-person dataset (optional)
python tools/preprocess.py --config configs/synthetic_small.yaml

# 2. Train
python tools/train.py --config configs/synthetic_small.yaml

# 3. Evaluate the best checkpoint
python tools/evaluate.py --config configs/synthetic_small.yaml --checkpoint runs/synthetic_small/best.pt

# 4. Visualise predictions vs. ground truth
python tools/visualize.py --config configs/synthetic_small.yaml --checkpoint runs/synthetic_small/best.pt --video
```

Any config field can be overridden on the command line, e.g.:

```powershell
python tools/train.py --config configs/synthetic_small.yaml train.max_epochs=30 data.batch_size=4
```

## Data format

The dataset (`unified_perception.data.MultiViewPoseDataset`) reads:

```
<root>/index.json                   # {"train": [...], "val": [...]}
<root>/<split>/<seq>/calib.npz      # K (N,3,3), R (N,3,3), T (N,3) world->cam, width, height
<root>/<split>/<seq>/poses.npz      # keypoints (F,Pmax,J,3) mm, valid (F,Pmax) bool
<root>/<split>/<seq>/images/f{t:03d}_c{c:03d}.png
```

Calibration convention (matching `human_prior`): `X_cam = R @ X_world + T`,
`u,v = (K @ X_cam) / z`. All world coordinates are in **millimetres**.

### Using real data (human_prior aligned outputs)

Set `data.provider: human_prior_aligned` and point to the alignment outputs
generated by `human_prior/src/data/align_camera_mocap/run_pipeline.py`.

```yaml
data:
  provider: human_prior_aligned
  human_prior_repo: ../human_prior
  human_prior_aligned_dirs:
    - ../human_prior/test_output_h36m_batch
    - ../human_prior/test_output_moyo
    - ../human_prior/test_output_mpi3dhp
  human_prior_h36m_dataset_path: <h36m_root>
  human_prior_moyo_dataset_path: <moyo_root>
  human_prior_mpi_dataset_path: <mpi_root>
```

This backend reads `mocap_keypoints.json` and `alignment_results.json`, then
uses human_prior dataset adapters to stream calibrated camera frames.

## Outputs

`MultiViewPoseDataset` yields per-window tensors:

| key | shape | notes |
|---|---|---|
| `imgs` | `(T, N, 3, H, W)` | normalised RGB |
| `world2img` | `(T, N, 4, 4)` | `K4 @ [R\|T]` projection |
| `intrinsics` | `(T, N, 4, 4)` | padded `K` |
| `gt_keypoints` | `(T, Pmax, J, 3)` | world mm |
| `gt_valid` | `(T, Pmax)` | person presence mask |

The model returns per-decoder-layer `cls_scores (L,B,T,Q,1)` and normalised
`keypoints (L,B,T,Q,J,3)`; `model.denormalize_keypoints` maps them to world mm.
